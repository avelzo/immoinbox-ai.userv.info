# Authentification — correctif du 3 novembre 2026

Better Auth 1.7.10 attend le champ standard utilisateur `image`. Il était absent
du schéma et du client Prisma 6.19.3 généré. Le contrôle de schéma bloquait les
requêtes d'authentification avec `SCHEMA_MISMATCH`, même si le build réussissait.
La recette isolée reproduit bien ce refus avec l'ancien client.

## Correctif appliqué

Ajout de `image String?` à User, puis `prisma generate`. Le champ est optionnel
et MongoDB n'impose pas de colonne : aucun `db push`, migration, nouvel index,
seed ou changement d'utilisateur existant. Un document sans propriété image
est lu avec image=null. Les versions et dépendances restent identiques.

Le processus PM2 `immoinbox-ai-dev` a été redémarré sous deploy pour recharger le
client et vider le diagnostic de schéma mis en cache par Better Auth. Le mode
dev, le port 3016 et la configuration existante sont conservés. Aucun autre
processus n'a été redémarré pour cette intervention.

## Vérifications

- Échec `user.image` reproduit avant correction sur MongoDB éphémère.
- Inscription, connexion et session sur base isolée avec l'authentification de
  l'application, pas une imitation de l'adaptateur.
- Ancien utilisateur sans propriété image : connexion réussie, image=null.
- Mauvais mot de passe refusé, session invalidée à la déconnexion.
- Playwright : page privée redirigée sans session, connexion puis inscription
  via les formulaires, arrivée sur le tableau de bord.
- Le navigateur de recette bloque les requêtes hors de son origine locale.
- Validation/génération Prisma, tests de sécurité Prisma, lint, typage et build
  réussis ; aucun diagnostic de schéma manquant dans le nouveau build.
- Après redémarrage : login/register et get-session 200, session anonyme null,
  tableau de bord redirigé vers la connexion, aucun nouveau schema mismatch.
- Audit de production sans vulnérabilité.

Le rattachement de démonstration à une même agence reste inchangé. Cette recette
ne vaut pas validation d'un nouveau fonctionnement multi-organisations. Aucun
email réel n'a été lu ou analysé et aucun compte de test créé dans la base active.

## Rejouer la recette

`npm run test:auth` exige DATABASE_URL vers un replica set MongoDB éphémère sur
127.0.0.1, port explicite différent de 27017 et base préfixée
`immoinbox_auth_test_`. BETTER_AUTH_URL doit valoir http://127.0.0.1:8795 ; utiliser
un BETTER_AUTH_SECRET fictif. Ne pas charger l'environnement de l'application
active. La base de test est supprimée en fin de recette.

Pour la recette navigateur, compiler le candidat avec cette même URL publique
locale, puis passer IMMOINBOX_HTTP_SMOKE=1 et IMMOINBOX_PLAYWRIGHT_PATH vers une
installation de Playwright dédiée aux tests. Le script lance lui-même le serveur
de recette sur 127.0.0.1:8795. Aucun paquet de test n'est ajouté au runtime.
